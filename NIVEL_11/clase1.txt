**OWASP** son las siglas de **Open Worldwide Application Security Project** (Proyecto Abierto de Seguridad de Aplicaciones Web).

Es una comunidad internacional sin fines de lucro enfocada en mejorar la seguridad del software. Su objetivo principal es hacer que la seguridad de las aplicaciones sea visible, comprensible y accesible para desarrolladores, arquitectos, auditores y empresas de todo el mundo.

### Puntos clave de OWASP

* **Proyectos Abiertos y Gratuitos:** Todo el material de OWASP (documentos, herramientas, guías y estándares) está disponible bajo licencias abiertas y sin costo.
* **El "OWASP Top 10":** Es su proyecto más célebre. Consiste en un informe de concientización que se actualiza periódicamente y enumera los 10 riesgos de seguridad más críticos en las aplicaciones web (por ejemplo, inyecciones SQL/NoSQL, fallas en el control de acceso o fallos criptográficos).
* **Independencia Técnica:** No está vinculada a ninguna empresa comercial ni promueve tecnologías propietarias, lo que garantiza imparcialidad en sus análisis y metodologías.
* **Estándares y Herramientas:** Además del Top 10, desarrolla estándares globales de seguridad como **ASVS** (Application Security Verification Standard), guías de pruebas de penetración (**OWASP Testing Guide**) y herramientas de código abierto como **OWASP ZAP** (Zed Attack Proxy) para análisis de vulnerabilidades.

OWASP Top 10 para LLM
El OWASP Top 10 para Aplicaciones con LLM (Modelos de Lenguaje de Gran Escala) es un marco de seguridad creado por la Open Worldwide Application Security Project para identificar, concientizar y mitigar los diez riesgos y vulnerabilidades más críticos al integrar IA generativa en aplicaciones de software.   A diferencia del OWASP Top 10 tradicional para aplicaciones web, este estándar aborda la naturaleza no determinista de los LLMs, donde el código y los datos en lenguaje natural comparten el mismo canal de procesamiento.   Riesgos Principales (OWASP Top 10 para LLM)LLM01: Inyección de Prompts (Prompt Injection)   Manipulación Directa (Jailbreaking): El usuario altera las instrucciones del sistema (system prompt) para eludir restricciones o barreras de seguridad.   Inyección Indirecta: El modelo procesa información maliciosa proveniente de sitios web, documentos o correos externos (por ejemplo, vía RAG o lecturas web) que contiene instrucciones ocultas para tomar el control de la conversación o realizar acciones no autorizadas.   LLM02: Divulgación de Información Sensible (Sensitive Information Disclosure)   Exposición accidental de datos de identificación personal (PII), credenciales, claves API o propiedad intelectual memorizada durante el entrenamiento o inyectada en el contexto (RAG).   LLM03: Agencia Excesiva (Excessive Agency)   Ocurre cuando se le otorgan al modelo o agente demasiadas herramientas, permisos, accesos a APIs o autonomía sin suficiente supervisión humana o validación previa.   LLM04: Vulnerabilidades en la Cadena de Suministro (Supply Chain)   Riesgos derivados de utilizar modelos preentrenados de terceros, conjuntos de datos alterados, conectores (MCP servers), complementos o librerías comprometidas.   LLM05: Envenenamiento de Datos y Modelos (Data and Model Poisoning)   Manipulación maliciosa de los datos de preentrenamiento, fine-tuning o bases de conocimiento RAG para introducir puertas traseras (backdoors), sesgos severos o degraciones en el comportamiento del modelo.   LLM06: Consumo ilimitado de Recursos (Unbounded Consumption / Denial of Wallet)   Ataques dirigidos a agotar los recursos de cómputo, memoria o presupuesto (vía llamadas masivas a APIs o bucles recursivos de razonamiento), causando denegación de servicio o costos imprevistos.   LLM07: Desinformación / Confianza excesiva (Misinformation / Overreliance)   Riesgos provocados cuando el modelo genera respuestas falsas o alucinaciones con alta elocuencia y estas son tomadas como válidas sin validación, derivando en decisiones erróneas o fallas de cumplimiento legal/técnico.   LLM08: Exposición de Contexto Oculto y Prompts (Hidden Context / System Prompt Exposure)   Fuga de reglas de negocio, lógica interna o instrucciones confidenciales integradas directamente dentro del system prompt del agente o aplicación.   LLM09: Debilidades en Vectores y Embeddings (Vector & Embedding Weaknesses)   Vulnerabilidades específicas en la generación, almacenamiento o recuperación de embeddings en bases de datos vectoriales (RAG) que permiten inyectar contenido o alterar la semántica de la búsqueda.   LLM10: Manejo Inseguro de Salidas (Improper Output Handling)   Falta de validación o sanitización de las respuestas del modelo antes de enviarlas a componentes secundarios (como navegadores web, comandos de terminal o bases de datos), lo que habilita fallos como XSS, SSRF o ejecución remota de código.   Ecosistema de Seguridad Complementario (Agentes IA)A la par de la lista de LLM, OWASP también mantiene el OWASP Top 10 for Agentic Applications (ASI), diseñado para arquitecturas autónomas que planifican y ejecutan acciones en múltiples pasos (abordando riesgos como Agent Goal Hijack, uso indebido de herramientas e identidades abusadas).

**MCP** son las siglas de **Model Context Protocol** (Protocolo de Contexto de Modelo). Es un estándar abierto creado por Anthropic para unificar y estandarizar la forma en que los modelos de inteligencia artificial (LLMs) y los agentes conversacionales se conectan con fuentes de datos externas, herramientas, sistemas de archivos y bases de datos.

A menudo se le describe como **"un puerto USB-C para la IA"**, ya que proporciona una interfaz universal y segura que evita tener que desarrollar conectores y APIs personalizadas desde cero cada vez que un modelo necesita interactuar con un nuevo sistema o repositorio.

### Componentes Principales de la Arquitectura MCP

* **Hosts (Anfitriones):** Las aplicaciones de IA, plataformas de chat o entornos de desarrollo que inician la necesidad de acceder a información externa.
* **Clients (Clientes):** Los módulos internos del host que establecen y mantienen una comunicación bidireccional y segura con los servidores de contexto.
* **Servidores MCP:** Aplicaciones ligeras y especializadas que exponen de forma controlada recursos específicos (como una base de datos SQL, un servidor de archivos local, repositorios de código o herramientas de automatización).

### Ventajas Clave del Protocolo

* **Interoperabilidad Universal:** Cualquier cliente o modelo compatible con MCP puede conectarse de inmediato a cualquier servidor MCP disponible sin necesidad de reescribir la lógica de integración.
* **Seguridad y Aislamiento:** Permite otorgar a los asistentes de IA acceso a entornos locales o corporativos de forma modular, definiendo permisos estrictos sobre qué datos y herramientas se exponen.
* **Desarrollo de Agentes Avanzados:** Facilita la creación de flujos donde los agentes de IA pueden leer documentos, consultar bases de datos relacionales o interactuar con APIs de manera estructurada y predecible.

Un **AI-BOM** (Artificial Intelligence Bill of Materials o Lista de Materiales de Inteligencia Artificial) es un inventario formal y estructurado que detalla todos los componentes, dependencias, librerías, modelos, conjuntos de datos y artefactos de software que conforman un sistema o aplicación basada en inteligencia artificial.

Al igual que un SBOM tradicional en ciberseguridad, su objetivo es proporcionar visibilidad completa de la cadena de suministro de software, facilitando la auditoría de vulnerabilidades, el cumplimiento normativo (como la Ley de IA de la Unión Europea) y la identificación de riesgos técnicos u operativos asociados a cada elemento.

### Solución Sencilla: Chatbot con RAG y Análisis de Riesgo

Tomemos como ejemplo un chatbot minimalista con **RAG (Retrieval-Augmented Generation)** compuesto por los siguientes 4 componentes principales:

1. **Modelo de Lenguaje (API de Terceros):** Conexión vía API a un LLM comercial para generar las respuestas.
2. **Base de Datos Vectorial (Local / Embebida):** Almacenamiento local de *embeddings* (ej. ChromaDB o FAISS) para buscar fragmentos de documentos corporativos.
3. **Librería de Orquestación y RAG (Python):** Framework para coordinar el flujo de consulta, recuperación y envío al LLM (ej. LangChain o LlamaIndex).
4. **Librería de Procesamiento de Documentos (Python):** Herramienta para leer y extraer texto de PDFs u otros formatos (ej. PyPDF o python-docx).

| Componente del AI-BOM | Tipo / Tecnología | Riesgo Más Alto Identificado (OWASP / Suministro) |
| --- | --- | --- |
| **1. Modelo LLM** | API Externa (ej. Gemini API / OpenAI) | **Divulgación de Información Sensible / Dependencia Externa:** Envío accidental de datos confidenciales de la empresa a la API del proveedor o interrupción del servicio (*Downtime* del proveedor). |
| **2. Base Vectorial** | Base de datos embebida (ej. ChromaDB) | **Envenenamiento de Datos (*Data Poisoning* / RAG Injection):** Inyección de contenido malicioso en los documentos indexados que altere el comportamiento del bot o extraiga información no autorizada. |
| **3. Orquestador RAG** | Librería Open Source (ej. LangChain) | **Vulnerabilidades en la Cadena de Suministro (*Supply Chain Attacks*):** Inclusión de dependencias de terceros comprometidas con código malicioso en el repositorio del framework. |
| **4. Extractor de Docs** | Librería Open Source (ej. PyPDF) | **Manejo Inseguro de Archivos / Desbordamiento:** Procesamiento de archivos PDF maliciosos o corruptos diseñados para explotar vulnerabilidades de memoria o ejecución de código en la librería de lectura. |

Al migrar de una API en la nube a una infraestructura local basada en **Ollama y Llama 3**, el perfil de riesgo cambia drásticamente: se eliminan los riesgos de privacidad con proveedores externos, pero surgen nuevos desafíos relacionados con la **gestión de infraestructura local, seguridad del runtime y consumo de recursos de hardware**.

### Cambios Clave en el Perfil de Riesgo (Local vs. Cloud)

* **Privacidad y Datos Sensibles:** A diferencia de una API comercial, los datos de la empresa y las consultas no salen del servidor local, mitigando el riesgo de *Divulgación de Información Sensible* hacia terceros (cumpliendo normativas estrictas de secreto bancario o confidencialidad).
* **Superficie de Ataque en Redes Locales:** Al correr servicios como Ollama localmente, si no se configuran correctamente las redes virtuales (Docker networks o *binding* a `127.0.0.1`), cualquier script malicioso ejecutado en la máquina o red local podría interactuar directamente con el modelo sin controles de identidad.
