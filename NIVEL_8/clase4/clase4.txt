Escenario 
La app ya genera respuestas, pero cualquier persona puede usarla y ver todas las generaciones. Se debe 
proteger el acceso y garantizar que cada usuario vea únicamente su propio historial, aplicando límites 
distintos según su plan. 
Objetivos de aprendizaje 
• Implementar registro, inicio y cierre de sesión. 
• Configurar reglas de privacidad que aíslen los datos de cada usuario. 
• Aplicar límites por plan antes de llamar a la API. 
Desarrollo paso a paso 
Paso 1. Ampliar el usuario (15 min) 
• Agregar al tipo User: plan (conjunto de opciones Plan), creditos, usos_hoy, 
fecha_ultimo_uso. 
• Crear el tipo Config con limite_gratis = 5 y limite_pro = 100.

Paso 3. Flujos de autenticación (30 min) 
Flujos principales 
Registro:  Registrar usuario (correo, contraseña)            → establecer plan = Gratis, usos_hoy = 0            → ir a la página "app" Login:     Iniciar sesión → ir a la página "app" Logout:    Cerrar sesión → ir a "inicio" Protección: Al cargar la página "app", si el usuario no ha iniciado sesión → ir a "login" 
 
Paso 4. Reglas de privacidad (30 min) 
• Para Generation: “Cuando el creador es el usuario actual” → puede ver todos los campos y 
buscar en listas. 
• Para User: el resto de usuarios no puede ver campos de otros; plan y creditos no se modifican 
desde el navegador. 
• Crear la regla por defecto “Todos los demás”: sin acceso. 
Paso 5. Límite por plan y reinicio diario (25 min) 
Lógica del límite 
Antes de llamar a Gemini:   Si fecha_ultimo_uso ≠ hoy → usos_hoy = 0 y fecha_ultimo_uso = hoy   Límite = (plan = Pro) ? limite_pro : limite_gratis   Si usos_hoy >= Límite → mostrar "Alcanzaste tu límite diario" y no llamar a la API
